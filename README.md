# Spokemon

Vue 3 + Vite + Vue Router + Pinia, Node.js HTTP 서버 + Turso/libSQL 학습 앱입니다. **Node.js 24**가 필요합니다. 서버 DB는 `@libsql/client` 비동기 API를 사용합니다.

## 실행

```powershell
cd D:\game
npm install
npm run server
```

다른 터미널에서:

```powershell
cd D:\game
npm run dev -- --host 127.0.0.1 --port 5188
```

[앱 열기](http://127.0.0.1:5188/). 개발 서버의 `/api` 요청은 3199 포트의 API 서버로 전달됩니다. `npm run build` 결과는 API 서버의 [빌드 미리보기](http://127.0.0.1:3199/)에서도 볼 수 있습니다. `npm run preview`만으로는 API가 연결되지 않으므로 전체 앱 확인은 API 서버 또는 개발 서버를 사용하세요.

## 최초 관리자 생성 (비밀번호 하드코딩 없음)

서버를 실행한 PC에서 아래 명령을 실행합니다. 비밀번호는 12자 이상으로 직접 입력하며 코드·명령 기록에 평문으로 넣지 않습니다.

```powershell
cd D:\game
$adminSecret = Read-Host '관리자 비밀번호 (12자 이상)' -AsSecureString
$adminPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($adminSecret)
try {
  $env:SPOKEMON_ADMIN_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($adminPointer)
  npm run admin:create -- --login teacher --name '선생님'
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($adminPointer)
  Remove-Item Env:SPOKEMON_ADMIN_PASSWORD -ErrorAction SilentlyContinue
}
```

이 계정으로 로그인하면 관리자 페이지로 이동합니다. 관리자 생성 CLI는 기존 계정을 덮어쓰거나 승격하지 않습니다. 실제 관리자 비밀번호나 기본 관리자 계정은 코드에 포함하지 않았습니다. 학생 회원가입 API는 `role=admin`을 거부하고 반은 서버에서 ‘미배정’으로 고정합니다.

## 관리자 사용 순서

1. 학생이 회원가입하거나 기존 로컬 계정으로 로그인합니다.
2. 관리자 페이지에서 기수를 등록하고 학생별 기수를 지정합니다.
3. 기수·과목을 선택하고 체크박스로 공개할 학습 항목을 개별 선택합니다. 기본값은 전체 잠금입니다.
4. 학생 대시보드에서 학생명·기수·공개 진도 기준 진행률·오답·누적 시간·최근 학습일을 확인합니다. 검색·기수·과목 필터와 학생 상세를 제공합니다.

과목당 100문제(객관식 60, 주관식 40), 5단원 × 20학습 항목입니다. 기존 문제 ID를 보존하며 객관식은 12개, 주관식은 8개씩 단원에 순서대로 배정했습니다. 한 회차 최대 25문제(객관식 15+주관식 10)를 공개 진도에서 출제하며 공개 항목이 적으면 그 수만 출제합니다. 새 출제는 아직 출제하지 않은 문제를 우선 사용합니다. 관리자 공개 범위를 다시 줄여도 완료·오답·퀴즈·포인트 기록은 삭제하지 않습니다.

## 학생 학습과 포인트

- 로그인 후 `/student`에서 오늘/누적 공부시간과 과목별 진행률을 봅니다. 진행률 = 공개 항목 중 완료 수 / 공개 항목 수이며 분모가 0이면 0%입니다.
- 학습 페이지에서 읽은 항목을 완료 표시하거나 퀴즈 정답을 맞히면 완료가 기록됩니다. 학습 완료 표시는 포인트를 지급하지 않습니다.
- **퀴즈 문제별 최초 정답에만 20코인**을 서버에서 즉시 지급합니다. 오답 복습에서 처음 맞혀도 지급하며 일반 퀴즈·복습 전체를 통틀어 한 번입니다. 퀴즈 종료 화면은 해당 회차에 실제로 받은 포인트만 표시합니다.
- 카드게임은 8단계 클리어 보상(3~50코인)을 지급합니다. 신규 가입 보너스는 없으며 기존 포인트는 아래 이전 절차로 보존합니다.
- 펫 먹이/놀이/꾸미기의 코인 차감과 캐릭터 저장도 서버에서 처리합니다.
- ‘마이 리틀 펫 → 틀린 문제!’는 과목별 필터·재풀이·복습 상태·오답 횟수를 제공합니다. 잠근 문제는 제목·정답·해설을 보내지 않고 잠금 안내만 표시합니다.

## 기존 로컬 기록 이전과 보존

기존 `pocket-accounts-v1`과 `pocket-arcade-v1`는 삭제하거나 초기화하지 않습니다. 기존 로컬 아이디/비밀번호로 로그인하면 로컬 해시를 확인한 후 학생 서버 계정을 생성하고 기존 계정의 코인·캐릭터·게임·학습·오답 원본을 이전 신청으로 DB에 보관합니다. **기존 코인은 임의 초기화하지 않으며, 서버 잔액 반영은 관리자 검토·승인 후 한 번만** 수행합니다. 승인 전 계정 화면에 이전 대기 코인 수를 표시합니다.

학생이 수정 가능한 브라우저 값을 자동 신뢰하지 않기 위해 관리자 승인 절차를 사용합니다. 관리자 학생 상세에서 원본 JSON과 기존 코인을 확인할 수 있습니다. 승인 시 기존 잔액을 현재 서버 잔액에 더하며, 기존 완료 퀴즈에서 보상받은 정답은 재지급되지 않도록 보상 이력을 등록합니다. 원본에는 기존 포인트 내역과 학습 이력도 그대로 남습니다. DB의 `migrations.snapshot`이 보존 원본입니다. 같은 이전 신청은 두 번 승인해도 중복 적립하지 않습니다.

## 공부시간

학습 단원·문제 풀이·오답 복습 화면에서만 활동을 관찰하고 약 10초마다 서버에 저장합니다. 일반 게임·대시보드·메뉴 선택 시간은 제외합니다. 실제 브라우저 입력·스크롤·터치 이벤트를 관찰하며 숨긴 탭 또는 마지막 활동 후 5분이 지나면 정지하고 활동하면 재개합니다. 페이지 이동 시 이벤트와 타이머를 제거하고 마지막 구간을 전송합니다.

서버는 사용자별 단일 탭 임대, 순번 검증, 서버 경과시간 상한으로 중복·재전송 적립을 차단합니다. 클라이언트가 전달한 누적 초를 신뢰하지 않습니다. 연결이 끊어진 긴 구간은 활동을 입증할 수 없어 적립하지 않습니다. 일별 시간은 UTC+9(한국 시간) 자정에서 나누고 과목별·전체 시간을 보관합니다. 네트워크 상태에 따라 마지막 수 초는 아직 전송되지 않았을 수 있습니다.

## DB와 보안 경계

운영 DB: 서버 환경변수 `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`으로 Turso libSQL에 접속합니다. 운영 환경에서는 누락 시 로컬 DB로 전환하지 않습니다. 개발 중 두 변수가 없을 때만 `server/data/spokemon.sqlite` 또는 `SPOKEMON_DB`를 libSQL 파일 드라이버로 사용합니다. `.env`와 DB/백업은 Git에서 제외합니다. 기존 SQLite를 읽기 전용으로 별도 이전하는 절차와 Render Free 설정은 [RENDER.md](RENDER.md)에 있습니다.

비밀번호는 무작위 salt와 scrypt 해시, 세션은 무작위 토큰의 해시를 DB에 저장합니다. 브라우저는 HttpOnly/SameSite 쿠키만 보유하며 사용자 ID·권한을 요청 본문에서 신뢰하지 않습니다. 모든 관리자 API, 학생 소유권, 단원·문제 접근은 서버에서 검사합니다. 보상은 libSQL 쓰기 트랜잭션과 `(user_id, question_id)` 고유 키로 중복을 막고 ledger에 기록합니다. 문제은행과 정답은 `server/questions/`에 있으며 클라이언트 번들에 포함하지 않습니다. 개발 서버도 서버 파일과 DB 경로를 차단합니다.

기본 서버는 127.0.0.1:3199에만 바인딩됩니다. 다른 환경에서 사용할 때는 HTTPS와 `COOKIE_SECURE=true`, 정확한 `APP_ORIGIN`을 설정해야 합니다. `API_PORT`, `API_HOST`로 서버 주소를 조정할 수 있습니다. 개발 모드는 로컬 주소만 허용합니다.

## 검증

```powershell
npm run test:server
npm run build
```

검증은 독립 메모리 DB·테스트 HTTP 서버를 사용하며 실제 사용자 DB를 건드리지 않습니다. 권한 승격/타인 조회/CSRF 차단, 기수별 단원 잠금과 재잠금, 동시 요청 보상 1회 지급, 기존 코인 이전 1회 승인, 한국 날짜·숨김·5분 유휴·복수 탭·재전송 시간 처리를 검사합니다. 브라우저 전체 흐름 검증 스크립트도 `scripts/verify-browser.cjs`에 제공합니다.

갈무리 폰트 라이선스: `public/licenses/galmuri-OFL.md`. 사용자가 제공한 로고·배경·캐릭터·카드 이미지를 유지했습니다.

브라우저 검증은 `npm run test:browser`로 실행합니다. Windows의 Microsoft Edge가 있으면 이를 사용하며, 그 외에는 `npx playwright install chromium`으로 테스트용 Chromium을 설치하세요. 검증은 실제 사용자와 분리된 메모리 DB와 브라우저를 사용합니다. 관리자 생성 명령과 파일 DB 재시작 보존도 `test:server`에 포함됩니다.

## 비공개 쪽지: 질문있어요!
학생은 상단 ‘질문있어요!’ 모달에서 과목·제목(100자)·내용(5000자)을 관리자에게 보냅니다. 별도의 공개 게시판은 없습니다. ‘마이 리틀 펫 → 내 쪽지함’에서 본인 발신 질문과 관리자 답장만 조회합니다. 답장을 열면 그때 받은 답장 ID만 읽음 처리하므로 새로 도착한 다른 답장을 잘못 읽음 처리하지 않습니다. 마이 리틀 펫·내 쪽지함에 읽지 않은 답장 수를 표시하고 보이는 탭에서 15초마다 갱신합니다.
관리자는 관리자 페이지의 학생 쪽지함에서 학생명/아이디·기수·과목·답변 상태로 필터링하고 답장을 보냅니다. 대시보드에 전체 답변 대기 건수를 표시합니다. DB의 private_messages/private_replies/mail_requests에 저장하며 HttpOnly 로그인 세션으로 권한·소유권을 검사합니다. 요청 식별자로 재전송을 멱등 처리하고 동일 내용의 60초 이내 중복도 막습니다. 기존 계정과 기록은 변경하지 않습니다.
쪽지 검증: `npm run test:mail`, `npm run test:mail:browser`. 독립 DB와 브라우저로 소유권, 관리자 필터, 동시 중복 전송, 실제 모달 전송·답장·읽음 표시와 재시작 보존을 확인합니다.

학습 범위는 관리자 선택창과 학생 화면에 과목별 전체 학습명을 표시합니다. 표시 이름은 src/data/curriculum.js에서 관리하며 기존 단원 번호·공개 범위·완료 기록은 유지합니다.

기수별 공개 범위는 관리자 화면에서 체크박스로 개별 선택합니다. 예: 1·3번째 항목만 공개할 수 있으며 2번째는 계속 잠깁니다. 기존 누적 공개 설정은 동일한 항목 선택으로 자동 이전하며 완료·오답·포인트 기록은 유지합니다. 기수는 관리자가 등록하고 학생별로 배정합니다. 내부 classes/class_id API 필드는 기존 DB 호환을 위해 유지합니다.

포켓몬 파트너는 최초 선택 후 서버에서 고정됩니다. 기존 학생은 현재 포켓몬이 유지·고정되며, 다른 포켓몬으로 변경하는 API 요청은 409로 차단합니다. 동일 선택 재전송은 안전하게 처리하고 닉네임 변경·돌보기·꾸미기는 계속 가능합니다.

마이 리틀 펫의 꾸미기 상점은 빨간 도감 형태의 9칸 아이템 슬롯으로 표시합니다. 리본·왕관·모자를 선택해 구매·착용하고 해제할 수 있습니다. 보유·착용 여부와 코인은 서버 응답을 표시하며 빈 슬롯은 비활성화됩니다. 포켓몬 최초 선택 고정 규칙은 유지합니다.

첫 진입은 로그인 화면으로 연결하며 로그인 전에는 게임 메뉴를 표시하지 않습니다. 로그인 후 기존 홈과 학습·게임 화면을 이용합니다.

인트로 화면은 제거되어 `/`에서 기존 홈이 바로 열립니다. 관리자 루트 접속은 관리자 페이지로 이동합니다. 퀴즈 풀이 중에는 소개·단계 안내를 접고 문제와 답안을 좌우로 배치하며, PC에서는 제출·다음 버튼이 화면 아래에 유지되는 집중 레이아웃을 사용합니다. 모바일은 읽기 쉬운 세로 배치로 표시합니다.

로그인 전에는 게임 메뉴를 숨기고 로그인 화면으로 이동합니다. 로그인·회원가입은 빨간 도감 형태의 전용 화면을 사용합니다. 카드게임은 전용 인트로와 레벨 선택을 제공하고 플레이 중에는 화면 크기에 맞춰 최대 30장을 자동 배치합니다. 카드 진행은 화면을 나가거나 새로고침하면 초기화되며 포인트·캐릭터·학습 기록은 유지됩니다.

지하철 운영은 메뉴와 홈에서 제거했습니다. 기존 저장 기록은 보존하며 이전 /metro 주소는 홈으로 이동합니다. 꾸미기 아이템은 18종이며 도감 슬롯에서 9개씩 2페이지로 확인·구매·착용합니다. 가격과 구매 가능 여부는 서버에서 검증합니다.

## 직접 문제 만들기
AI 생성 기능은 제거했습니다. 문제 제작소에서 객관식·주관식을 추가해 최대20문제를 한 번에 저장·공유할 수 있습니다. 여러 문제는 개별 원본 문제로 게시됩니다. API 키가 필요하지 않습니다. 단원 미정은 unit=0으로 저장하며 공식 진도율에 포함하지 않습니다. 지정 단원의 진도 잠금과 기존 포인트 규칙은 유지됩니다. 일괄 저장은 한 트랜잭션으로 처리하고 요청 ID로 중복 저장을 차단합니다.

## 관리자 콘텐츠 / 쪽지 관리

- 관리자 페이지 → 과목·단원 / 공식 문제 관리: 과목과 단원을 직접 등록하고 객관식·주관식 공식 문제를 추가·수정할 수 있습니다. 드롭다운과 학생 퀴즈·학습 진도에 함께 반영됩니다. 새 단원은 기수별로 공개해야 학생이 접근할 수 있습니다.
- 공식 문제의 수정 버전은 원본 ID를 유지하므로 최초 정답 포인트가 중복 지급되지 않습니다. 기존 완료 기록도 원본 기준으로 유지됩니다. 학생은 공식 출처를 지정하거나 관리자 등록 API를 사용할 수 없습니다.
- 관리자 학생 쪽지함의 ‘학생에게 쪽지 쓰기’에서 학생 검색 후 먼저 발신할 수 있습니다. 학생은 내 쪽지함에서 확인·답장할 수 있고 읽지 않은 관리자 쪽지가 알림에 반영됩니다.
- 관리자·학생·친구 쪽지의 삭제는 본인 목록만 숨기며, 상대방의 쪽지와 원본 DB 기록은 유지합니다. 다른 학생의 쪽지를 조회·삭제할 수 없습니다.
- 배포 시 새 테이블만 추가하며 기존 계정·포인트·기록을 초기화하지 않습니다. `npm run test:admin-features`에서 권한, 동시 발신, 진도, 보상, PC·모바일 화면을 검증합니다.

## 관리자 보너스 포인트 지급

관리자 페이지의 **학생 포인트 지급**에서 학생 이름/아이디를 검색하고 학생을 선택한 뒤, 정수 금액(1회 1~1,000,000 P)과 사유(최대 200자)를 입력합니다. 지급 확인 창에서 대상·금액·지급 후 잔액을 확인하고 확정합니다. 관리자 이름·사유·금액·시간은 학생의 포인트 내역과 관리자 지급 내역에 남습니다. 삭제된 학생 계정과 관리자 계정은 지급 대상이 될 수 없으며, 학생은 지급 API를 호출할 수 없습니다. 같은 요청 식별자의 중복 요청은 한 번만 반영하고 내용이 바뀐 재사용은 거부합니다. 관리자 보너스는 퀴즈 최초 정답 보상·학생 제작 문제의 일일 한도와 별도로 기록합니다. 기존 잔액과 내역을 초기화하지 않습니다. 검증: `npm run test:admin-points`.

## 관리자 메뉴 / 새 쪽지 알림 / 접속자 표시

- 관리자 페이지를 학생 현황, 과목·공식 문제, 포인트 관리, 학생 쪽지함, 기수·진도의 다섯 메뉴로 나눴습니다. 상단 요약 카드로 학생 수·평균 진도·답변 대기·기수를 확인하고 해당 메뉴로 이동합니다. 선택 메뉴는 URL에 유지됩니다.
- 관리자 쪽지, 학생의 관리자 쪽지, 친구 쪽지에서 각 쪽지함 전체 삭제를 지원합니다. 확인 후 본인 목록만 숨기며 상대방 기록과 친구 목록은 유지합니다. 새 답장이 도착하면 숨긴 대화도 다시 표시됩니다.
- 로그인 중 15초 간격으로 새 수신 쪽지를 확인해 화면 팝업을 띄웁니다. 관리자에게는 학생 질문/추가 답장, 학생에게는 관리자 쪽지/답장과 친구 쪽지를 알립니다. 쪽지 ID로 구분해 미확인 개수가 같아도 새 쪽지를 감지합니다. 계정별로 표시한 알림 ID만 브라우저에 저장하고, 지원 브라우저에서는 Web Locks로 여러 탭의 중복 팝업을 막습니다. 팝업을 닫아도 읽음 처리되지 않으며 실제 대화를 열 때 읽음 처리합니다. 브라우저가 닫혀 있거나 탭이 숨겨진 동안의 OS 알림은 아닙니다.
- 로그인 오른쪽 접속자 칸에 현재 접속중/인원을 표시합니다. 기본 9칸을 유지하며 9명 초과 시 그 영역만 스크롤합니다. 서버도 9명으로 잘라 반환하지 않습니다.
- 펫 꾸미기는 캐릭터 이미지에 묶어 확대·축소하고, 포켓몬별 머리/눈/장식 위치를 사용합니다. 왕관·모자, 안경·고글, 헤드폰, 꽃 장식을 구분하며 아이템 슬롯 미리보기에도 같은 배치를 적용합니다.
- 검증: `npm run test:mail-bulk`, `npm run test:wear-online`.

### 파트너 스킨

마이 리틀 펫의 스킨 상점에서 현재 강화 단계에 맞는 스킨을 1단계 500P·2단계 1,000P·3단계 1,500P에 구매합니다. 기존 1단계는 팬텀 5종·꼬부기 5종·팽도리 6종·이상해씨 6종이며, 진화형 8종에는 각 2개씩 16종의 투명 스킨을 추가했습니다. 원본 이미지를 그대로 사용하므로 사진에 포함된 배경도 유지됩니다. 적용 범위는 돌보기 네모칸 중앙 이미지뿐이며 배경·테두리·장식·꾸미기 아이템·아이템창·프로필·접속자 이미지는 바뀌지 않습니다.

구매 내역과 파트너별 선택 스킨은 서버의 pet JSON에 저장됩니다. 재적용과 기본 스킨 복귀는 무료이며, 파트너를 변경해도 구매 스킨 소유권은 보존되며 현재 강화 단계와 다른 스킨은 잠깁니다. 가격·현재 파트너·소유권·잔액 검증과 차감 및 구매 원장 기록은 한 쓰기 트랜잭션에서 처리합니다. `npm run test:skins`로 중복 구매, 권한, 잔액, 저장, 화면 적용 범위와 모바일 상점을 검증합니다.

### 카드 클리어 보상과 활동 팝업

카드게임은 8단계(8·12·18·24·30·36·42·48장)입니다. 단계별 클리어 보상은 3·5·10·15·20·25·30·50코인이며, 새 판을 완료하면 다시 받을 수 있습니다. 서버가 섞은 덱과 뒤집기·짝 맞추기 상태를 검사하고, 완료 처리와 원장 기록·코인 지급을 한 트랜잭션에서 처리합니다. 같은 판의 완료 요청을 재전송하거나 동시에 보내도 한 번만 지급합니다. 클라이언트에는 현재 공개된 카드만 전달하고 카드가 맞지 않으면 단계별 지연 후 다시 뒤집힙니다.

친구 요청 수신 시 수락/나중에 팝업, 전송 시 완료 팝업을 제공합니다. 퀴즈·관리자 지급·카드 클리어 등의 양수 포인트 원장은 지급 사유와 수량을 팝업으로 표시합니다. 기능 도입 이전의 포인트 내역은 팝업으로 다시 표시하지 않으며 내역은 보존됩니다. 새 알림은 화면이 보일 때 15초마다 확인하며, 본인 보상 직후에는 즉시 확인합니다. 서버의 사용자별 확인 기록과 브라우저의 사용자별 중복 표시 방지 기록을 함께 사용합니다. 홈 메뉴는 제거하고 로고로 홈에 이동합니다. `npm run test:cards-alerts`로 검증합니다.

### 숨은그림 찾기

홈의 네 번째 준비중 카드를 숨은그림 찾기로 교체했습니다. 기존 프로젝트 사진 10장을 배경으로 쓰며 총 10단계, 매 라운드 목표 이모지는 10개입니다. 뒤 단계일수록 방해 이모지가 많고 조금 더 희미하게 숨습니다. 목표와 동일한 이모지는 방해 항목에 배치하지 않으며, 위치를 분리해 모바일 터치 영역이 겹치지 않도록 구성했습니다.

힌트 3회, 찾은 목록·시간·실수 표시, 재시작·다음 단계·메인 이동을 제공합니다. 시간 제한과 실수 감점은 없습니다. 재시작하면 위치와 목표가 새로 섞이며 화면을 나가면 진행 중 게임은 초기화됩니다. 10개 전부 찾으면 서버 트랜잭션으로 3포인트를 지급하고 포인트 수령 팝업을 표시합니다. 같은 판의 마지막 발견을 동시에 여러 번 요청해도 한 번만 지급됩니다. `npm run test:hidden`으로 전 단계·보상·힌트·접근 권한·PC 및 모바일 터치를 검증합니다.

### 게임 명예의 전당

카드 뒤집기와 숨은그림 찾기의 시작 화면·플레이 화면·완료 화면에서 명예의 전당을 열 수 있습니다. 게임별·단계별 개인 최고 기록 TOP20과 내 순위·기록을 표시하고 현재 1·2·3위에게 금·은·동메달을 표시합니다. 순위가 바뀌면 메달도 변경되며 별도 포인트 보상이나 꾸미기 아이템은 추가하지 않습니다.

시작·완료 시간을 서버에서 계산하고 게임 완료·코인 지급·순위 기록을 동일한 쓰기 트랜잭션에 저장합니다. 클라이언트가 보낸 완료 시간은 사용하지 않습니다. 기록은 빠른 시간, 적은 시도 횟수(숨은그림은 실수·힌트 횟수), 먼저 완료한 순서로 결정합니다. 같은 사람은 각 단계에서 한 자리만 차지하며 삭제된 계정은 순위에서 제외됩니다. 기존 완료 기록은 서버 보상 원장과 게임 시작 시간을 통해 한 번 복원하고 코인은 재지급하지 않습니다. `npm run test:rankings`로 검증합니다.

학생 상단 메뉴에도 숨은그림 찾기 바로가기 버튼을 제공합니다. 홈 네 번째 카드와 상단 메뉴 양쪽에서 같은 게임으로 이동합니다.

### 파트너 강화·별명·단계별 스킨

팽도리→팽태자→엠페르트, 꼬부기→어니부기→거북왕, 팬텀→메가팬텀→거다이맥스 팬텀, 이상해씨→이상해풀→이상해꽃의 3단계 형태를 제공합니다. 투명 진화 이미지 8장과 HOME/색이 다른 진화형 스킨 16장은 공개 PokéAPI 자료를 원본 그대로 로컬에 저장했습니다. 출처는 `public/images/evolutions/SOURCES.md`, `public/images/skins/evolved/SOURCES.md`에 기록합니다.

Lv.10·20·30…에 도달하면 자동 판정 대신 ‘강화하시겠습니까?’ 창이 표시됩니다. 거절하면 현재 형태·스킨을 유지하고 해당 기회는 종료됩니다. 수락하면 불꽃 연출을 보여주고 서버의 `crypto.randomInt(100)` 값 0~9에서만 성공하는 10% 판정으로 한 단계 강화합니다. 성공 시 하트, 실패 시 비와 ‘강화에 실패하였습니다’ 팝업을 표시합니다. 실패하면 현재 계열의 최초 형태(1단계)로 돌아가며 레벨·아이템·구매한 스킨은 보존됩니다. 강화 자체에는 추가 비용이 없습니다. 최종 3단계에는 새 기회가 생기지 않으며 기존 고레벨은 다음 구간부터 시작합니다.

다른 캐릭터 계열로 변경하면 새 캐릭터의 강화 전 1단계로 초기화됩니다. 같은 캐릭터 재선택으로는 초기화하거나 재추첨하지 않습니다. 기존 강화 기록은 보존하고, 기회·선택·성공/실패·결과 확인을 서버 pet JSON에 저장합니다. 동일 기회에 대한 중복 수락은 한 번만 판정하며 거절 후 수락으로 바꾸는 요청은 거부합니다. 연출 중 새로고침하거나 연결이 끊겨도 저장된 결과를 다시 표시하므로 네트워크 오류를 강화 실패로 취급하지 않습니다.

스킨은 총 38종(기존 22종 + 진화형 16종)이며 1단계 500P, 2단계 1,000P, 3단계 1,500P입니다. 현재 강화 단계와 같은 스킨만 구매·착용할 수 있고 다른 단계는 자물쇠 화면으로 표시하며 서버에서도 차단합니다. 구매한 스킨은 없어지지 않으며 해당 단계가 되면 무료 재적용할 수 있습니다. 강화 결과 직후 새 모습을 표시하도록 선택 스킨은 기본으로 전환합니다. 스킨은 계속 돌보기 중앙 이미지에만 적용됩니다.

‘파트너 이름 정하기’에서 공백 정리 후 1~12글자 별명을 무료로 저장합니다. 계정 닉네임과 별도로 관리하며 강화·캐릭터 변경·새로고침 후에도 보존합니다. `npm run test:evolution`, `npm run test:skins`로 선택/확률/중복 요청/잠금/가격/별명/모바일/연출을 검증합니다.

접속중 목록에는 계정 아이디·닉네임을 표시하지 않으며 `/api/online` 응답에도 포함하지 않습니다. 포켓몬의 현재 강화 모습과 실제 보유·착용 중인 아이템만 작은 아바타로 표시합니다. 9명 초과 내부 스크롤과 빈 슬롯은 유지합니다.
